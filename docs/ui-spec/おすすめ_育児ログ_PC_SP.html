1. 画面の目的と導線

実際の育児上の困りごと、試したこと、結果を読む一覧です。正規URLは /logs/、各カード押下先は /logs/:id/ です。

PC

ログカードを2〜3列のグリッドで表示。データ量に応じて実装のブレークポイントで列数が変わる。

SP

ログカードを1列で表示。日付、月齢、いいね、困りごと、やってみたこと、結果を縦に整理。

3. 表示・検索・絞り込み・並び替え

機能仕様
表示logs content collectionを logNumber降順で初期表示。PCはmdで2列、lgで3列、SPは1列。
検索カードの全文（タイトル、やってみたこと、結果など）に対する小文字化部分一致。入力イベントごとに更新。
絞り込みカテゴリーと対象月齢。カテゴリー・月齢・検索はAND条件。適用中はボタンをmint系で強調。
並び替え最新順＝data-lognumber降順。月齢が低い順／高い順＝数値比較。月齢未指定は最後。
空状態条件に一致するカードが0件なら「条件に一致する子育てログはありません。」を表示。
シート絞り込み・並び替えとも下端から上へ開く同一シート。ハンドルの下スワイプ、背景クリックで閉じる。

4. データのキャッシュ・保存法則

  • ログ本文・カード情報はAstroの logs content collectionからビルド時に静的生成。
  • 検索・カテゴリー・月齢・並び順は画面内メモリのみ。リロードすると初期値へ戻り、URL／IndexedDBには保存しない。
  • カードのいいね状態・件数は共通のいいね処理を使用。件数は接続可能ならSupabase、匿名押下状態はIndexedDB article_likes、通信不能時は件数0へフォールバック。
  • 画像が存在しないログは、現在のキャプチャのように画像プレースホルダーを表示する。

5. 実装上の根拠
